Attention is a content-addressable lookup. For every token, a model decides which other tokens matter right now, then gathers information from them in proportion to that relevance.

NotationB batchT sequence lengthD model widthH query headsd head width

Why attention?

A recurrent model carries a fixed-size summary forward through a sequence. Attention removes that bottleneck: each position can directly read from every earlier position. It is both wonderfully expressive and, for long sequences, expensive.

Each token produces three learned representations: a query that asks for information, a key that says what it can be matched on, and a value that carries the information to return.

SCALED DOT-PRODUCT ATTENTION

Attention(Q, K, V) = softmax QKT√dk V

The dot product between a query and every key produces relevance scores. Scaling by √dk keeps the softmax in a useful range; the resulting weights form a weighted sum of values.

Multi-head attention

One attention operation may only learn one kind of relationship. Multi-head attention (MHA) gives the model several smaller attention spaces, or heads, in parallel. A head may track syntax, an antecedent, or a nearby formatting pattern; the model is free to learn the division of labour.

states[B, T, D]
→
Q₁ K₁ V₁Q₂ K₂ V₂Q₃ K₃ V₃H independent heads
→
output[B, T, D]

For each head h, the input X ∈ ℝT×D is projected into query, key, and value vectors of width d = D/H. The independent head outputs are concatenated and projected back to width D:

MULTI-HEAD ATTENTION

Qh=XWhQ, Kh=XWhK, Vh=XWhV
headh=softmax QhKhT√dVh
MHA=Concat(head1…headH)WO

This implementation makes the tensor moves explicit: the projections become [B, H, T, d], then each token is prevented from reading future tokens by a causal mask.

PYTORCH REFERENCE · MULTI-HEAD ATTENTION

import math
import torch
from torch import nn

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, n_heads):
        super().__init__()
        assert d_model % n_heads == 0
        self.h, self.d = n_heads, d_model // n_heads
        self.q = nn.Linear(d_model, d_model, bias=False)
        self.k = nn.Linear(d_model, d_model, bias=False)
        self.v = nn.Linear(d_model, d_model, bias=False)
        self.out = nn.Linear(d_model, d_model, bias=False)

    def split_heads(self, x):  # [B,T,D] -> [B,H,T,d]
        B, T, _ = x.shape
        return x.view(B, T, self.h, self.d).transpose(1, 2)

    def forward(self, x):
        B, T, D = x.shape
        q, k, v = map(self.split_heads, (self.q(x), self.k(x), self.v(x)))
        scores = q @ k.transpose(-2, -1) / math.sqrt(self.d)  # [B,H,T,T]
        future = torch.ones(T, T, device=x.device, dtype=torch.bool).triu(1)
        weights = scores.masked_fill(future, float("-inf")).softmax(-1)
        y = weights @ v                                        # [B,H,T,d]
        y = y.transpose(1, 2).contiguous().view(B, T, D)
        return self.out(y)                                     # [B,T,D]
The inference catch. During autoregressive generation, the model keeps past keys and values in a KV cache. With MHA this cache has one K and V vector per head, per past token, in every layer—so it grows quickly with context length.

Multi-query attention (MQA)

MQA keeps multiple query heads but shares one key head and one value head. Each query can still ask a distinct question, but all queries read from the same cached memory.

Q₁Q₂Q₃Q₄many query heads
→
KVone shared KV head

This reduces KV-cache memory and cache bandwidth by approximately the number of heads. It is especially valuable at serving time, when memory movement often dominates the cost of producing the next token. The trade-off is capacity: query heads cannot retain independent views of the past.

MQA changes only the K and V projections. Queries retain H heads, while K and V each have one. The same cached K and V are used for every query head:

MULTI-QUERY ATTENTION

Q=XWQ ∈ ℝT×H×d
K=XWK, V=XWV ∈ ℝT×1×d
headh=softmax QhKT√dV

expand below creates a view—rather than H copies—of the shared K/V head. In a decode loop the cache itself is therefore H times smaller than MHA’s.

PYTORCH REFERENCE · MULTI-QUERY ATTENTION

import math
import torch
from torch import nn

class MultiQueryAttention(nn.Module):
    def __init__(self, d_model, n_heads):
        super().__init__()
        assert d_model % n_heads == 0
        self.h, self.d = n_heads, d_model // n_heads
        self.q = nn.Linear(d_model, d_model, bias=False)  # H query heads
        self.k = nn.Linear(d_model, self.d, bias=False)   # one KV head
        self.v = nn.Linear(d_model, self.d, bias=False)
        self.out = nn.Linear(d_model, d_model, bias=False)

    def forward(self, x):
        B, T, D = x.shape
        q = self.q(x).view(B, T, self.h, self.d).transpose(1, 2)
        k = self.k(x).unsqueeze(1)                        # [B,1,T,d]
        v = self.v(x).unsqueeze(1)
        k = k.expand(-1, self.h, -1, -1)                  # shared views
        v = v.expand(-1, self.h, -1, -1)
        scores = q @ k.transpose(-2, -1) / math.sqrt(self.d)
        future = torch.ones(T, T, device=x.device, dtype=torch.bool).triu(1)
        y = scores.masked_fill(future, float("-inf")).softmax(-1) @ v
        y = y.transpose(1, 2).contiguous().view(B, T, D)
        return self.out(y)

Grouped-query attention (GQA) is the practical middle ground: it uses fewer KV heads than query heads, with each KV head shared by a group of queries. Many current models choose GQA rather than the full sharing of MQA.

Multi-head latent attention (MLA)

DeepSeek’s MLA takes a different route. Rather than storing full keys and values—or simply sharing them—it first compresses each token’s KV state into a small latent vector. That latent is what enters the cache.

token stateht
→
KV latentctKV
→
K / Vreconstructed for heads

At a high level, MLA factorizes the usual key and value projections through this compact bottleneck. It can preserve richer head-specific information than MQA while caching far fewer numbers than MHA. Extra care is needed for positional encodings: applying RoPE to a compressed key naively breaks the ability to absorb projections. MLA therefore separates a small position-carrying key component from the compressed content component.

LATENT KV COMPRESSION

ctKV = WdownKV ht    ;    Kt, Vt = WupK,V ctKV

More explicitly, split each head into content dimensions dc and RoPE dimensions dr. The cache holds the compact latent cKV and a small position-only key kR. A query is the concatenation q=[qC;qR] and likewise k=[kC;kR]. This keeps RoPE outside the compressed path.

DECOUPLED POSITIONAL ENCODING

cKV=WdownKVx ; kC=WupKcKV ; vC=WupVcKV
qR=RoPE(WQRx) ; kR=RoPE(WKRx)

This pedagogical version reconstructs content K/V from the latent so that the computation is easy to follow. Production MLA can algebraically absorb some up-projections into the query path; the cache-saving structure remains the same.

PYTORCH REFERENCE · MULTI-HEAD LATENT ATTENTION

import math
import torch
from torch import nn

def rope(x):  # [B,H,T,d_rope], d_rope must be even
    d = x.size(-1)
    positions = torch.arange(x.size(-2), device=x.device, dtype=x.dtype)
    inv_freq = 1 / (10000 ** (torch.arange(0, d, 2, device=x.device, dtype=x.dtype) / d))
    angle = torch.outer(positions, inv_freq)               # [T,d/2]
    cos, sin = angle.cos()[None, None], angle.sin()[None, None]
    even, odd = x[..., 0::2], x[..., 1::2]
    return torch.stack((even * cos - odd * sin, even * sin + odd * cos), -1).flatten(-2)

class MultiHeadLatentAttention(nn.Module):
    def __init__(self, d_model, n_heads, latent_dim, rope_dim):
        super().__init__()
        assert d_model % n_heads == 0 and rope_dim % 2 == 0
        self.h, self.dr = n_heads, rope_dim
        self.dc = d_model // n_heads - rope_dim
        assert self.dc > 0
        self.q_content = nn.Linear(d_model, n_heads * self.dc, bias=False)
        self.q_rope = nn.Linear(d_model, n_heads * rope_dim, bias=False)
        self.kv_down = nn.Linear(d_model, latent_dim, bias=False)  # cache this
        self.k_up = nn.Linear(latent_dim, n_heads * self.dc, bias=False)
        self.v_up = nn.Linear(latent_dim, n_heads * self.dc, bias=False)
        self.k_rope = nn.Linear(d_model, rope_dim, bias=False)     # shared KV rope key
        self.out = nn.Linear(d_model, d_model, bias=False)

    def forward(self, x):
        B, T, D = x.shape
        q_c = self.q_content(x).view(B,T,self.h,self.dc).transpose(1,2)
        q_r = rope(self.q_rope(x).view(B,T,self.h,self.dr).transpose(1,2))
        latent = self.kv_down(x)                                  # [B,T,latent_dim]
        k_c = self.k_up(latent).view(B,T,self.h,self.dc).transpose(1,2)
        v = self.v_up(latent).view(B,T,self.h,self.dc).transpose(1,2)
        k_r = rope(self.k_rope(x).unsqueeze(1)).expand(-1,self.h,-1,-1)
        q, k = torch.cat((q_c,q_r), -1), torch.cat((k_c,k_r), -1)
        scores = q @ k.transpose(-2, -1) / math.sqrt(q.size(-1))
        future = torch.ones(T,T,device=x.device,dtype=torch.bool).triu(1)
        y = scores.masked_fill(future, float("-inf")).softmax(-1) @ v
        # Pad the value's content part before the usual output projection.
        y = torch.cat((y, torch.zeros_like(q_r)), -1).transpose(1,2).reshape(B,T,D)
        return self.out(y)

Sparse attention

Sparse attention is the general idea of not giving every query a full, expensive read of the past. A model first identifies a small candidate set, then uses normal attention on only those candidates. The candidates can be individual tokens, as in DSA, or learned blocks of tokens, as in CSA. This section introduces the principle before the specific DeepSeek designs that apply it.

DeepSeek Sparse Attention (DSA)

DeepSeek-V3.2 is the first model in this sequence to make the read pattern sparse. MLA already reduces the size of each cached entry. DSA decides that a query should read only a small number of those entries. It retains the MLA cache and adds a separate, inexpensive lightning indexer that ranks past tokens before main attention runs. [V3.2]

What DSA changes

Without DSA, a token’s main attention queries every earlier MLA latent in the context. With DSA, the indexer first gives each earlier token a relevance score. Main attention receives the Top-K highest-scoring MLA entries, not the whole context. The selected entries are still processed by the normal attention calculation. The indexer chooses where to read, while main attention decides how much each chosen entry contributes.

MLA cacheone latent per past token
→
lightning indexerscores all past tokens
→
Top-K tokens2,048 in sparse training
→
MLA attentionreads selected latents

LIGHTNING INDEXER

It,s = Σj wt,jI · ReLU(qt,jI · ksI)
St = TopK(It,: ),   ut = Attention(ht, {cs | s ∈ St})

For query position t and earlier position s, the indexer adds scores from a few small heads. The ReLU removes negative matches. The learned weight lets the current token favour useful indexer heads. This score is not an attention weight and it does not mix values. It is a cheap retrieval score. After selection, normal MLA attention reads the chosen latent values. V3.2 uses MLA in an MQA-like form at this point, so the selected KV latent is shared across query heads.

How DSA learns not to hide useful evidence

An untrained selector would discard useful tokens. V3.2 first runs dense attention, freezes the main model, and trains only the indexer to match the distribution of attention mass made by the existing dense heads:

Lindex = Σt DKL(pt,: || softmax(It,: ))

After 1,000 warm-up steps, Top-K selection is enabled and the full model trains on the sparse pattern. The indexer keeps its alignment loss, while the main model keeps the language-model loss. This makes the selector imitate useful dense reads before the model has to rely on it.

What DSA saves, and what it still pays for

Main attention now processes k values rather than the full length L, reducing that part of the work from O(L2) to O(Lk). The lightning indexer still scores the full history, so DSA is not a fully linear method. It is valuable because scoring with small vectors is far cheaper than reading full main-attention representations. DSA selects individual token latents. The V4 methods below go a step further by compressing neighbouring tokens into blocks before retrieval.

Sparse attention: important implementation trade-offs

Dense attention compares a query with every cached key. Its cost grows with context length because every new token must score and read the entire history. Sparse attention changes the read pattern. A cheaper indexer identifies a small number of candidate blocks, then the normal, more expensive attention calculation runs only on those blocks.

A useful classification. CSA and HCA are attention mechanisms because they define the keys, values, and positions that a query reads. CSA2 is also an attention mechanism, but it adds an execution schedule: some layers create an index while others reuse one. KV-cache quantization is separate. It changes storage precision, not what is attended to.

The trade-off is directness. Dense attention can compare every token with every earlier token. Sparse attention reads only selected memory entries, so its indexer must retain the blocks that matter. Long-context systems often keep a local window of recent, uncompressed tokens because nearby syntax, the latest instruction, and recent tool output are unusually important.

Compressed Sparse Attention (CSA)

CSA, introduced in DeepSeek-V4, has two stages. It first compresses neighbouring KV entries along the sequence, then uses a lightweight indexer to choose a Top-K subset of those compressed entries for core attention. The sparse search therefore runs over a shorter learned representation of history, rather than over individual token entries. [V4]

1. Compress a block into one memory entry

Let H be a run of hidden states. CSA projects them into candidate keys and values, then combines each group of m adjacent positions into one compressed entry. The weights are learned from a second projection, so this is not fixed average pooling. The model can place more of a block’s information into its summary when that information is useful for later retrieval.

C = HWKV,   Z = HWZ
Kcompr = Σi=1m softmax(Zr,i) CKr,i,   Vcompr = Σi=1m softmax(Zr,i) CVr,i

V4 forms overlapping compressed views so a boundary token is not forced into only one summary. This reduces the number of global entries by roughly the compression factor while retaining alternatives near block boundaries.

past tokensfull sequence
→
learned compressionone entry per block
→
Top-K blockslightweight indexer
→
core attentionselected global memory

2. Retrieve compressed blocks, then use real attention

The CSA indexer scores compressed keys, selects the best blocks, and passes their compressed keys and values to main attention. The model does not expand a selected block back into its original tokens. It attends to the learned block representation. That is the central accuracy and efficiency trade-off.

It,r = index(qt, kcompr),   Rt = TopK(It,: )
ot = Attention(qt, KcompRt, VcompRt)

CSA uses a shared KV representation for the sparse global path, much like MQA, while keeping many query heads. This makes each retrieved global entry economical to store and read. Partial RoPE preserves positional information in a subset of dimensions, and attention sinks give the model stable always-available positions.

k, v = self.kv(blocks).chunk(2, dim=-1)
compressed_k = (weights[..., None] * k).sum(2)
compressed_v = (weights[..., None] * v).sum(2)
indices = index_scores.topk(top_k, dim=-1).indices
global_output = attend_selected(q, compressed_k, compressed_v, indices)

3. Keep a precise local window

CSA adds uncompressed sliding-window attention alongside the sparse global path. The local window can still resolve immediate relationships at token resolution, such as a closing delimiter, a function argument, or the last tool result. The global path provides broad retrieval. The local path protects short-range precision that aggressive compression can lose.

Qwen Sparse Attention (QSA)

QSA is Qwen3.8-Flash-Next’s sparse attention mechanism. Like CSA, it first reduces the search space and then runs a more expensive read on selected material. The difference is where compression happens. CSA creates learned compressed keys and values that core attention reads directly. QSA uses a compressed representation only for the indexer. Once it selects a micro-block, main attention expands that block back into its original tokens and reads those token-level keys and values. [QSA]

1. Score blocks, not every token

The QSA indexer first projects each token into a small shared key. It groups non-overlapping runs of r keys, averages each group, and normalises the result. Small query heads score these block keys. This changes the indexer’s sequence length from n token entries to about n/r block entries.

raw token keysone per past token
→
average micro-blocksone index key per block
→
Top-K blockscompressed MQA indexer
→
core attentionexpanded token entries

QSA BLOCK INDEXER

k̂b = RMSNorm(AvgPool(kbr : br+r−1))
Ii,b = Σh ReLU(⟨RoPE(qih, i), RoPE(k̂b, br)⟩)
Bi = TopK⌈K/r⌉(Ii,: )

QSA applies RoPE after averaging a micro-block. That detail avoids averaging keys that already carry different rotary angles. The block receives one position, its first token position. A block may only be selected when its final token is in the query’s past. The unfinished current block is included directly, which preserves the most recent local context.

2. Expand selected blocks back to precise token reads

The selected block indices are expanded into their original token indices. Main attention then runs on those original token KVs, rather than on an averaged block value. QSA therefore loses detail only during retrieval. Once a block has passed the indexer, attention can still distinguish the individual words, code tokens, or image-related tokens inside it. This is its key difference from CSA and HCA.

DSA, CSA, and QSA select at different levels. DSA ranks individual cached token entries. CSA ranks learned block summaries and reads those summaries. QSA ranks averaged block keys, then reads the original tokens inside selected blocks. All three reduce the expensive core read, but QSA also reduces the indexer’s own long-context cost.

3. Train the selector before relying on it

QSA is introduced through continued pre-training in two stages. Dense distillation teaches the block indexer to match a pooled version of the full-attention distribution. Sparse training then turns on Top-K block selection and updates the full model. This is the same broad safety principle as DSA, but QSA’s teacher and selection units are blocks rather than individual tokens.

Heavily Compressed Attention (HCA)

HCA uses the same idea of learned sequence compression, but pushes it much harder. Its blocks are far larger than CSA’s blocks, and it does not run Top-K retrieval after compression. Instead, attention reads every entry in the now very short compressed sequence. [V4]

This makes HCA useful as a global, low-resolution memory channel. It has no sparse-indexer miss risk because every compressed block is visible. It has a larger information-loss risk because each block represents many more original tokens. V4 interleaves HCA with CSA and local sliding-window attention, giving different layers different views of the same long prompt.

scores = scores.masked_fill(block_end_after_query, float("-inf"))
output = torch.einsum("bthr,brd->bthd", scores.softmax(-1), values)

Compressed Sparse Attention 2 (CSA2)

CSA2 in DeepSeek-V4.1-Flash retains sparse, compressed global attention but focuses on work repeated across layers. In a normal stack, every layer would create KV entries, run its indexer, and select Top-K blocks. CSA2 lets some layers reuse earlier work when a new selection is unlikely to justify the memory traffic and indexer computation. [V4.1]

Full modecreates main KV, indexer K and Q, then fresh Top-K indices
Reindex modereuses main KV and indexer K, computes its own indexer Q and fresh Top-K indices
Reuse modereuses main KV and Top-K indices, skipping indexer work

All three modes still run the layer’s attention and feed-forward computation. What changes is the retrieval preparation. Full mode is the reference point. Reindex mode asks a new query what to retrieve from the same compressed memory. Reuse mode assumes the preceding layer’s retrieval set is good enough and reads that set directly.

PYTORCH REFERENCE · CSA2 PREPARATION MODES

if mode == "full":
    keys, values = self.compress(x)
    indices = self.index(x, keys)
elif mode == "reindex":
    keys, values = previous.keys, previous.values
    indices = self.index(x, keys)       # fresh query and Top-K
elif mode == "reuse":
    keys, values, indices = previous    # no new indexer work

output = attend_selected(q, keys, values, indices)

Hierarchical indexing narrows later searches

In the decoder, a later Full-mode layer can restrict its search to the candidate pool selected by an earlier Full-mode layer. This creates a hierarchy. An early layer performs a broad retrieval, and later layers spend their more precise retrieval budget inside that shortlist. The system retains the option to refresh indices at chosen layers rather than making every layer follow the same selection forever.

FP4 cache storage is related, but distinct

V4.1-Flash also stores main KV in FP4 with quantization-aware training. That halves the bytes used by those cache entries compared with an 8-bit representation. It complements CSA2, but it is not CSA2. CSA2 reduces which retrieval computations are performed. FP4 reduces the storage and bandwidth cost of the entries that still exist.

Choosing an attention design

Design KV cache Head diversity Typical use
MHA Large Highest Baseline / training
MQA Very small Lowest Fast decoding
GQA Medium High Modern LLM default
MLA Small latent High Long-context efficiency
DSA MLA cache, Top-K token reads High Sparse reads over long context
CSA Compressed blocks plus local window High Million-token global retrieval
QSA Token KV with compressed block index High Hybrid recurrent and sparse-attention models
HCA Heavily compressed global sequence High Low-resolution global memory
CSA2 Compressed sparse cache with reuse High Long-running agent decoding

These mechanisms solve the same operational problem: keep decoding fast as a sequence grows. MHA spends memory to maximise flexibility. MQA compresses decisively, GQA chooses a compromise, and MLA learns a compact memory representation. DSA makes reads selective. CSA and HCA add learned sequence compression. QSA compresses only the search index, then restores token detail for the selected read. CSA2 avoids repeating retrieval work across layers. The best choice depends on context length, the architecture around attention, and the serving hardware.
