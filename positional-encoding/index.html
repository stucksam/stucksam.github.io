Why position exists at all

Attention can tell which words are present, but not their order. Without extra information, it would treat “dog bites man” and “man bites dog” as the same collection of three word vectors—even though they mean very different things.

Positional encoding gives every token a clue about where it appears in the sequence. Some methods attach a position vector to each token, some add a distance-based adjustment when two tokens attend to one another, and some let the model infer order from another part of the architecture.

In more technical language: standard self-attention is permutation equivariant. If the inputs are reordered, its outputs are reordered in the same way; it does not independently recover the original order.

Absolute positions

The simplest approach adds one position vector pt to each token embedding xt. The vector may be learned as a table, or deterministic as in the original Transformer’s sinusoidal features.

ABSOLUTE SINUSOIDAL FEATURES

zt = xt + pt
pt,2i = sin(t / 100002i/D)   ;   pt,2i+1 = cos(t / 100002i/D)

Learned tables are flexible inside their training range but cannot directly represent unseen positions. Sinusoids extend indefinitely, although a model trained on short sequences can still fail at much longer ones.

import torch
from torch import nn

class LearnedAbsolutePositions(nn.Module):
    def __init__(self, max_len, d_model):
        super().__init__()
        self.table = nn.Embedding(max_len, d_model)

    def forward(self, x):                 # x: [B, T, D]
        positions = torch.arange(x.size(1), device=x.device)
        return x + self.table(positions)[None, :, :]

Relative position methods

Often the distance between two tokens matters more than their absolute addresses. Relative methods put the offset Δ = i−j directly into the score between query i and key j. T5 uses a learned, bucketed bias; ALiBi applies a head-specific linear penalty. Neither needs a position vector added to the residual stream.

Rotary Position Embeddings (RoPE)

RoPE is the dominant approach in modern decoder models. Instead of adding a vector to x, it rotates paired coordinates of Q and K by a position-dependent angle. A two-dimensional pair [a,b] becomes a point on a plane; later positions are rotated farther around that plane.

0qR(t)qθt

ONE ROTARY PAIR

R(θt) = cos θt−sin θtsin θtcos θt
q′t=R(θt)qt ; k′t=R(θt)kt

The key identity is what makes RoPE special: the dot product of a query at i and a key at j depends on their relative offset i−j, not their individual positions. Different coordinate pairs use different frequencies, so the model receives multiple distance scales.

THE RELATIVE-POSITION PROPERTY

(R(θi)q)TR(θj)k = qTR(θj−θi)k

PYTORCH REFERENCE · APPLYING ROPE

import torch

def apply_rope(q_or_k, base=10_000):
    # q_or_k: [B, H, T, d], with even d
    B, H, T, d = q_or_k.shape
    position = torch.arange(T, device=q_or_k.device, dtype=q_or_k.dtype)
    frequency = 1 / base ** (torch.arange(0, d, 2, device=q_or_k.device, dtype=q_or_k.dtype) / d)
    angle = torch.outer(position, frequency)             # [T, d/2]
    cos, sin = angle.cos()[None, None], angle.sin()[None, None]
    even, odd = q_or_k[..., 0::2], q_or_k[..., 1::2]
    return torch.stack((even*cos - odd*sin, even*sin + odd*cos), -1).flatten(-2)

# Apply after Q/K projection; do not rotate V.

RoPE beyond its training length

At long context, RoPE angles move into patterns the model did not see during training. The family of fixes changes the mapping from a token position t to a rotation angle.

Method Core idea Trade-off
Position interpolation Use t/s for extension factor s. Simple; usually needs fine-tuning.
NTK-aware scaling Adjust frequency base as context grows. Different handling of fine detail.
YaRN Blend scaling regimes and tune attention temperature. More knobs; practical recipe.
LongRoPE Search non-uniform scaling per dimension. Model-specific optimisation.

These are not magic switches. A context extension changes the model’s positional distribution; robust results normally require continued training or targeted fine-tuning at the new length.

No positional encoding (NoPE)

NoPE is not “the model has no order.” It means no explicit positional embeddings, relative bias, or RoPE are injected into the full-attention path. In a causal decoder, the triangular mask still exposes a token’s place: the first token can attend to one position, the next to two, and so on. The model can learn to use this asymmetric computation graph as an implicit clock.

t₀can see 1
t₁can see 2
t₂can see 3
t₃can see 4

causal visibility grows with position → implicit order signal

CAUSAL NOPE ATTENTION

scoreij = qikjT√d   where j ≤ i
scoreij = −∞   where j > i

That signal is weak and indirect in ordinary full attention, which is why NoPE has historically been risky for tasks needing exact absolute position or generalisation to novel lengths. But it becomes much more plausible in architectures with another ordered state mechanism. Kimi K3’s report describes NoPE in its full-attention layers while delegating positional information and recency bias to its recurrent gating/decay mechanism (Kimi Delta Attention). This is evidence for NoPE within a hybrid ordered architecture, not proof that causal masking alone replaces position everywhere.

PYTORCH REFERENCE · NOPE CAUSAL ATTENTION

import math
import torch
from torch import nn

class NoPECausalAttention(nn.Module):
    def __init__(self, d_model, n_heads):
        super().__init__(); assert d_model % n_heads == 0
        self.h, self.d = n_heads, d_model // n_heads
        self.qkv = nn.Linear(d_model, 3*d_model, bias=False)
        self.out = nn.Linear(d_model, d_model, bias=False)
    def forward(self, x):
        B, T, D = x.shape
        q, k, v = self.qkv(x).chunk(3, dim=-1)            # no position operation
        def heads(z): return z.view(B,T,self.h,self.d).transpose(1,2)
        q, k, v = map(heads, (q,k,v))
        scores = q @ k.transpose(-2,-1) / math.sqrt(self.d)
        future = torch.ones(T,T,device=x.device,dtype=torch.bool).triu(1)
        y = scores.masked_fill(future, float("-inf")).softmax(-1) @ v
        return self.out(y.transpose(1,2).contiguous().view(B,T,D))
A useful diagnostic. If you remove explicit position and a model still performs well, ask where the order signal moved. It may be the causal mask, convolution, recurrence, state decay, chunk boundaries, data formatting, or a combination.
