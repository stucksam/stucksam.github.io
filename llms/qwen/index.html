Qwen’s architecture story is not a series of unrelated model names. It is a steady effort to make longer inputs, larger parameter pools, and visual information cheaper to process, without losing the direct retrieval that makes Transformers useful.

Scope noteThis page covers general-purpose text LLMs and vision-language models. Audio, speech, image-generation, coding-only, mathematics-only, embedding, and guard-model branches are intentionally left for separate explainers.

1. The golden thread: spend compute where it changes the answer

Every Qwen generation still predicts the next token. What changes is the cost of deciding which earlier information to use and which parameters should process the current token. The early models are dense decoders. Qwen2 reduces decoding traffic with grouped-query attention. The vision branch learns to preserve an image’s real shape and a video’s timing. Later releases add sparse experts, hybrid sequence operators, and retrieval over compact memory blocks.

2. Qwen and Qwen-VL: establish the decoder and connect vision

The original Qwen family is a conventional dense, decoder-only Transformer. A token becomes a vector, passes through repeated attention and feed-forward layers, and produces a distribution for the next token. Attention allows a token to read earlier tokens. The feed-forward layer transforms each token independently after that read. Qwen’s value here is the baseline, because later Qwen releases change individual parts of this loop rather than discard it. [1]

Qwen1.5 is a bridge, not a new architecture chapter. Its 32B and 110B models use grouped-query attention, or GQA. Instead of storing a separate key and value for every query head, several query heads share one KV head. This reduces the cache stored during generation. Qwen2 later makes that choice standard across the family. [3]

2.1 Qwen-VL: turn image features into a sequence the decoder can read

Qwen-VL adds a visual receptor before the language model. The receptor divides an image into patches and turns them into visual feature vectors. A connector maps those vectors into the language model’s embedding width. The decoder then receives visual tokens beside text tokens. This is a simple but important separation of roles: the vision stack finds visual patterns, while the LLM relates those patterns to the question and writes the answer.

image
pixels→visual receptor
patch features→connector
LLM-width tokens→Qwen decoder
text answer

The original VL training pipeline first aligns images and text, then exposes the system to a broader mix of visual-language tasks, and finally tunes conversational use. Grounding data also teaches the model to connect words with image regions. The architecture is still a separate vision encoder plus a language decoder, rather than one network that receives raw pixels throughout. [2]

3. Qwen2 and Qwen2-VL: make memory and visual position practical

Qwen2 makes GQA a family-wide design choice. During autoregressive decoding, all past keys and values must be read again for every new token. If there are H query heads and G KV groups, each group serves H/G query heads. The cache therefore scales with G, not H.

Q ∈ ℝT×H×d,   K,V ∈ ℝT×G×d,   G < H
Several query heads read one shared key-value group.

This does not mean the query heads become identical. Each still forms its own query and attention weights. They simply read from a smaller set of cached key and value representations. Qwen2 also ships both dense models and a 57B-A14B MoE model. MoE therefore appears before Qwen3, even though Qwen3 makes it a more central family choice. [4]

3.1 Qwen2-VL: position has time, height, and width

Text has one natural position, its place in a sequence. Images and video have more: horizontal location, vertical location, and, for video, time. Qwen2-VL uses M-RoPE to assign separate position coordinates to those axes. The model can therefore distinguish a word in the top-left of a page from the same word in the bottom-right, and it can locate an event in a video rather than treating all frames as an unordered collection.

Naive Dynamic Resolution keeps an input image near its native aspect ratio and gives larger images more visual tokens. A 2×2 merger then combines nearby vision tokens before they reach the LLM. Video uses the same unified representation, with a shallow 3D convolution that groups small tubes across space and time. The point is not to preserve every pixel. It is to choose a token budget that tracks the information in the input. [5]

3.2 M-RoPE in detail: rotate different parts of the vector along different axes

Rotary position embeddings, or RoPE, do not add one position vector to a token. They rotate pairs of query and key dimensions by an angle determined by position. The dot product then depends on the distance between positions. Standard text RoPE uses one scalar position p. M-RoPE splits the positional dimensions into three bands and rotates each band using a different coordinate: time t, height h, and width w.

time band
t, frame or text orderheight band
h, vertical image positionwidth band
w, horizontal image position
q′ = [RoPE(qt, t) ; RoPE(qh, h) ; RoPE(qw, w)]
k′ = [RoPE(kt, t) ; RoPE(kh, h) ; RoPE(kw, w)]

For ordinary text tokens, Qwen2-VL assigns the same sequential position to all three coordinates. Text therefore behaves like normal one-dimensional RoPE. For an image patch, height and width come from its patch-grid location. For a video patch, time comes from its frame or temporal tube. This lets a language layer compare text with images and video without pretending that a two-dimensional page is a long row of unrelated patches.

M-RoPE gives the model coordinates, not visual understanding. The ViT still has to recognise strokes, objects, and motion. M-RoPE makes those features addressable in a way that preserves where and when they occurred. This matters for document questions such as “read the number in the bottom-right cell,” or video questions such as “what happened after the door opened?”

4. Qwen2.5 and long context: extend a mature decoder carefully

Qwen2.5 mainly improves data, post-training, tool use, and structured output. Its base LLM is not a replacement for the Qwen2 Transformer. The architecture-relevant branch is Qwen2.5-1M, which adapts a Qwen2.5 checkpoint to very long prompts. It trains progressively to 256K tokens, raises the RoPE base frequency, and uses Dual Chunk Attention to preserve relative-position behaviour when extrapolating toward one million tokens. Sparse attention in the serving stack speeds the expensive prompt-prefill phase. These are long-context techniques around the decoder, not a new universal layer type. [6]

4.1 Qwen2.5-VL: make the visual encoder cheaper without losing detail

Qwen2.5-VL refines the vision side. It uses full attention in a small number of ViT layers and window attention in the others. Window attention lets a patch attend only within a nearby region, so the expensive global comparison is not repeated in every vision layer. RMSNorm and SwiGLU make the visual blocks resemble efficient LLM blocks. The model also uses image coordinates, dynamic frame rates, and absolute-time M-RoPE IDs, which makes spatial and temporal references less ambiguous. [7]

5. Qwen3 and Qwen3-VL: sparse parameters and a controllable reasoning policy

Qwen3 keeps the efficient dense recipe of GQA, RoPE, SwiGLU, and pre-normalisation with RMSNorm. It removes QKV bias and adds QK-Norm, which normalises queries and keys before their dot product. That keeps attention scores in a more stable range during large-scale training. The major choice is that Qwen3 is released in both dense and MoE forms. [8]

5.1 MoE: choose a few feed-forward networks for each token

An MoE layer replaces one large feed-forward network with many experts. A router scores the experts for each token and sends the token to only the best few. Qwen3’s released MoE models have 128 experts and select eight per token. That gives the model a large total parameter pool while keeping the per-token calculation much smaller than running every expert.

token state→router
scores experts→E₁E₂E₃E₄E₅E₆→weighted sum
y = Σi ∈ TopK(r(x)) softmax(r(x))i · Ei(x)

The router needs balancing. If a few experts receive nearly all tokens, those experts become overloaded and the rest do not learn. Qwen3 uses global-batch load balancing, which measures routing across a wider batch rather than correcting every small local batch independently.

Qwen3’s thinking and non-thinking modes belong in a different box from this architecture. They are learned through a four-stage post-training process that includes a reasoning cold start, reinforcement learning, fusion with direct-answer data, and general RL. The same model weights can be prompted to show a reasoning trace or answer directly. This changes output behaviour and token budget, not the attention calculation. [9]

5.2 Qwen3-VL: send visual features into more than one language layer

Qwen3-VL keeps the vision encoder, merger, and Qwen3 decoder structure, but adds DeepStack. Instead of sending only the final vision-encoder features into the LLM, DeepStack injects features from several vision depths into corresponding language layers. Early visual layers can contribute local texture and text detail, while later layers contribute more abstract objects and relations. Interleaved M-RoPE and text timestamps extend the position scheme to long mixed image, video, and text histories. [10]

6. Qwen3-Next: use recurrence for most layers, attention at intervals

Qwen3-Next is the first large change to the sequence operator. The 80B-A3B model has 80B total parameters and activates about 3B per token. Its 48 layers are twelve repetitions of three Gated DeltaNet-plus-MoE layers followed by one Gated Attention-plus-MoE layer. In other words, 75% of token-mixing layers carry a fixed-size recurrent memory forward, while 25% still perform direct content-based lookup over the context. [17]

This is not a claim that recurrence is universally better than attention. The design assigns them different jobs. DeltaNet keeps processing cheap as the history grows, because its state does not grow with the number of earlier tokens. Gated Attention remains at regular intervals because it can retrieve one particular earlier token or passage directly. The official ablations compare the 75/25 hybrid with pure paths, rather than treating the hybrid as an arbitrary mixture.

6.1 Gated DeltaNet: update a memory state instead of storing every pairwise comparison

In full attention, each token compares its query with many earlier keys. A DeltaNet layer instead maintains a state matrix S. A new token writes a key-value association into that state, while a learned gate decides how much old state to retain. The query reads from the updated state. This is linear in sequence length for a fixed state size, but it cannot keep every past token as an independently addressable entry.

S̃t−1 = αtSt−1
et = vt − S̃t−1Tkt
St = S̃t−1 + βtktetT,   ot = StTqt

Here α decides how quickly old state fades and β controls the new write. The layer writes only the error between the current value and the value already recalled through the current key. Similar keys therefore revise an association instead of simply accumulating more outer products. Qwen’s configuration uses 16 query/key heads, 32 value heads, 128 dimensions per head, and a short causal convolution with kernel size 4 before the recurrent update. These details give the state a small local view before it has to compress the past. [18]

6.2 Gated Attention: retain a smaller number of exact global reads

The fourth layer in each group is still causal softmax attention. It uses an output gate, a 256-dimensional head, and RoPE on the first 64 dimensions of each head. The output gate can suppress an attention read when it is not useful. Qwen motivates this as a guard against low-rank behaviour, attention sinks, and large activations. The model has 16 query heads and 2 KV heads in these layers, so GQA limits cache traffic while the query heads remain diverse.

6.3 Sparse experts and multi-token prediction complete the efficiency design

Every token-mixing block is followed by an MoE feed-forward layer with 512 routed experts. The router selects ten routed experts and one shared expert for each token. Compared with Qwen3’s 128 experts and top-8 routing, this makes the parameter pool much larger while keeping only a small slice active. The release also normalises router initialisation and uses zero-centred RMSNorm with weight decay on norm weights to make the sparse, hybrid stack easier to train stably.

Qwen3-Next includes native multi-token prediction. Its auxiliary prediction path is trained for several draft steps, so its training task matches the speculative-decoding use at inference more closely than a one-step-only draft model. The public material supports that role, but does not establish a separate MTP layer count, so this guide does not infer one. The model is pretrained on 15T tokens sampled from the Qwen3 corpus, has a native 262K context window, and can be extended with YaRN toward roughly one million tokens. [17] [18]

7. Qwen3.5, 3.6, 3.7, and 3.8: retain the hybrid template

The later point releases should not be presented as four different Transformers. Qwen3.5 brings the Qwen3-Next hybrid of three Gated DeltaNet layers and one Gated Attention layer into a unified vision-language foundation. It retains sparse MoE, MTP, and a native 262K context that can extend toward one million tokens. [12]

Qwen3.6 retains that core layout. Its public release emphasises post-training and agent ergonomics, including keeping relevant reasoning history through tool use, rather than a new sequence block. Qwen3.7 is a hosted-product waypoint in the current public record, so this guide does not invent an architecture claim for it. Qwen3.8 scales the same template to 2.4T total parameters with 95B active parameters. The useful conclusion is that scale and training changed, while the published hybrid backbone remained recognisable. [13] [14]

8. Qwen3.8-Flash-Next: retrieve useful micro-blocks and add static n-gram memory

Qwen3.8-Flash-Next is the next clear architecture break. It is a multimodal MoE model and an early preview of the architecture intended for Qwen4. The official repository names four coupled changes: Gated DeltaNet plus Qwen Sparse Attention for token mixing, a four-branch Gated Residual stream, an offloaded n-gram embedding table, and an optimisation recipe built around Muon. The technical report matters because it records the ablations behind these choices, rather than only listing model features. [15] [16]

8.1 QSA: sparse attention whose indexer also scales with context length

Token-level sparse attention has a hidden cost. It may read only a few tokens in main attention, but its indexer still scores every query against every past token. QSA makes the indexer cheaper too. It splits past keys into non-overlapping micro-blocks of r tokens, averages each block into one index key, and scores those compressed keys. The indexer now makes about n/r comparisons per query rather than n.

k̂b = RMSNorm(AvgPool(kbr : br+r−1))
Ii,b = Σh ReLU(⟨RoPE(qih, i), RoPE(k̂b, br)⟩)
Bi = TopK⌈K/r⌉(Ii,: )

The order of operations is deliberate. QSA averages content before applying RoPE, then gives the resulting block a single position. Averaging already rotated keys would mix incompatible rotary phases. The indexer uses MQA, many small query heads with one shared key head, and partial RoPE on only part of each head. These choices keep it much smaller than the main attention path.

A selected block is expanded back into its original token positions for the core attention calculation. QSA also includes the recent unfinished micro-block, so the model does not lose the latest tokens just because a block has not closed. A query can select only a block whose last token is already in its past. QSA is therefore block-level retrieval followed by token-level attention inside the selected blocks.

Training QSADuring continued pre-training, dense distillation first teaches the indexer to match the backbone’s dense attention distribution after it has been pooled into blocks. Sparse training then enables Top-K block selection and adapts the backbone to this sparse pattern. This prevents an untrained selector from hiding useful evidence.

QSA does not reuse indices from a previous layer as CSA2 does. It compresses within its own layer, which suits a hybrid model where three GDN layers separate sparse-attention layers. Its compressed indexer reduces its own prefill cost from O(n2) to O(n2/r). Multi-token prediction can reuse QSA’s Top-K indices across speculative draft steps, where recomputing a near-identical retrieval set would waste work. [16]

8.2 Gated DeltaNet: targeted erase-and-write memory

Gated DeltaNet holds a fixed-size state matrix. First, a decay gate weakens old state. The layer then asks what value is already associated with the current key, and writes only the difference between that prediction and the current value. Similar keys revise an existing association rather than endlessly adding another copy.

S̃t−1 = αtSt−1
et = vt − S̃t−1Tkt
St = S̃t−1 + βtktetT,   yt = StTqt

Here α controls how long state survives and β controls the corrective write. Qwen applies short causal convolutions to Q, K, and V before this recurrence, which gives the layer a small local neighbourhood before it compresses information into state. Queries and keys are L2-normalised to bound the update. Periodic QSA remains necessary because no fixed-size state can preserve every distinct past token for later lookup. [16]

8.3 Gated Residual: four persistent streams with learned reads and writes

A standard Transformer has one residual stream. Flash-Next keeps four. Before a sublayer runs, each branch is independently RMS-normalised. A small gating network looks at all branches and assigns a separate gate to every branch and channel. The sublayer receives the average of those gated values.

x = ¼ Σc=14 Gc ⊙ RMSNorm(Rc)
R′c = Rc + sc · F(x)

The sublayer output is written back to every branch with a learned scalar strength s. The extra width is therefore usable, not merely duplicated. In the authors’ analysis, one branch tends to carry information across many layers while the other three retain more local updates. The gates also supply explicit rescaling, reducing activation outliers and improving stability at aggressive learning rates. The design removes a separate branch-mixing read that would add memory traffic during decoding. [16]

8.4 N-gram embedding: static capacity for familiar local patterns

The n-gram layer looks up embeddings for recent 2-, 3-, and 4-token sequences. It appears once, at layer 2, rather than in every layer. Its tables live in host memory and are prefetched asynchronously, so transfer overlaps with accelerator computation. This adds a large static lookup table without making every Transformer matrix larger.

The division of labour matters. The n-gram table helps with frequent local patterns, names, and code fragments. GDN carries an evolving compressed history. QSA retrieves detailed evidence from a long prompt. The n-gram table does not reason over a document and does not replace normal token embeddings.

8.5 The system, rather than one headline number

The published model has a 125B main model with 6B main-model parameters active per token and 51B n-gram embedding parameters held off accelerator. The paper compares it with the 397B-A17B predecessor at roughly one third of active parameters and training tokens, and about one ninth of training FLOPs. These are system-level results, not proof that a single module alone created the gain. The report’s useful lesson is that token mixing, residual scaling, memory placement, and optimisation have to be evaluated together. [15] [16]

How to read the lineage. GQA changes how much cached attention state is stored. M-RoPE changes how visual position is represented. MoE changes which feed-forward weights a token activates. Keeping these questions separate prevents “efficient” from becoming an empty label.
