Qwen’s architecture story is not a series of unrelated model names. It is a steady effort to make longer inputs, larger parameter pools, and visual information cheaper to process, without losing the direct retrieval that makes Transformers useful.

Scope noteThis page covers general-purpose text LLMs and vision-language models. Audio, speech, image-generation, coding-only, mathematics-only, embedding, and guard-model branches are intentionally left for separate explainers.

1. The golden thread: spend compute where it changes the answer

Every Qwen generation still predicts the next token. What changes is the cost of deciding which earlier information to use and which parameters should process the current token. The early models are dense decoders. Qwen2 reduces decoding traffic with grouped-query attention. The vision branch learns to preserve an image’s real shape and a video’s timing. Later releases add sparse experts, hybrid sequence operators, and retrieval over compact memory blocks.

2. Qwen and Qwen-VL: establish the decoder and connect vision

The original Qwen family is a conventional dense, decoder-only Transformer. A token becomes a vector, passes through repeated attention and feed-forward layers, and produces a distribution for the next token. Attention allows a token to read earlier tokens. The feed-forward layer transforms each token independently after that read. Qwen’s value here is the baseline, because later Qwen releases change individual parts of this loop rather than discard it. [1]

Qwen1.5 is a bridge, not a new architecture chapter. Its 32B and 110B models use grouped-query attention, or GQA. Instead of storing a separate key and value for every query head, several query heads share one KV head. This reduces the cache stored during generation. Qwen2 later makes that choice standard across the family. [3]

2.1 Qwen-VL: turn image features into a sequence the decoder can read

Qwen-VL adds a visual receptor before the language model. The receptor divides an image into patches and turns them into visual feature vectors. A connector maps those vectors into the language model’s embedding width. The decoder then receives visual tokens beside text tokens. This is a simple but important separation of roles: the vision stack finds visual patterns, while the LLM relates those patterns to the question and writes the answer.

image
pixels→visual receptor
patch features→connector
LLM-width tokens→Qwen decoder
text answer

The original VL training pipeline first aligns images and text, then exposes the system to a broader mix of visual-language tasks, and finally tunes conversational use. Grounding data also teaches the model to connect words with image regions. The architecture is still a separate vision encoder plus a language decoder, rather than one network that receives raw pixels throughout. [2]

3. Qwen2 and Qwen2-VL: make memory and visual position practical

Qwen2 makes GQA a family-wide design choice. During autoregressive decoding, all past keys and values must be read again for every new token. If there are H query heads and G KV groups, each group serves H/G query heads. The cache therefore scales with G, not H.

Q ∈ ℝT×H×d,   K,V ∈ ℝT×G×d,   G < H
Several query heads read one shared key-value group.

This does not mean the query heads become identical. Each still forms its own query and attention weights. They simply read from a smaller set of cached key and value representations. Qwen2 also ships both dense models and a 57B-A14B MoE model. MoE therefore appears before Qwen3, even though Qwen3 makes it a more central family choice. [4]

3.1 Qwen2-VL: position has time, height, and width

Text has one natural position, its place in a sequence. Images and video have more: horizontal location, vertical location, and, for video, time. Qwen2-VL uses M-RoPE to assign separate position coordinates to those axes. The model can therefore distinguish a word in the top-left of a page from the same word in the bottom-right, and it can locate an event in a video rather than treating all frames as an unordered collection.

Naive Dynamic Resolution keeps an input image near its native aspect ratio and gives larger images more visual tokens. A 2×2 merger then combines nearby vision tokens before they reach the LLM. Video uses the same unified representation, with a shallow 3D convolution that groups small tubes across space and time. The point is not to preserve every pixel. It is to choose a token budget that tracks the information in the input. [5]

4. Qwen2.5 and long context: extend a mature decoder carefully

Qwen2.5 mainly improves data, post-training, tool use, and structured output. Its base LLM is not a replacement for the Qwen2 Transformer. The architecture-relevant branch is Qwen2.5-1M, which adapts a Qwen2.5 checkpoint to very long prompts. It trains progressively to 256K tokens, raises the RoPE base frequency, and uses Dual Chunk Attention to preserve relative-position behaviour when extrapolating toward one million tokens. Sparse attention in the serving stack speeds the expensive prompt-prefill phase. These are long-context techniques around the decoder, not a new universal layer type. [6]

4.1 Qwen2.5-VL: make the visual encoder cheaper without losing detail

Qwen2.5-VL refines the vision side. It uses full attention in a small number of ViT layers and window attention in the others. Window attention lets a patch attend only within a nearby region, so the expensive global comparison is not repeated in every vision layer. RMSNorm and SwiGLU make the visual blocks resemble efficient LLM blocks. The model also uses image coordinates, dynamic frame rates, and absolute-time M-RoPE IDs, which makes spatial and temporal references less ambiguous. [7]

5. Qwen3 and Qwen3-VL: sparse parameters and a controllable reasoning policy

Qwen3 keeps the efficient dense recipe of GQA, RoPE, SwiGLU, and pre-normalisation with RMSNorm. It removes QKV bias and adds QK-Norm, which normalises queries and keys before their dot product. That keeps attention scores in a more stable range during large-scale training. The major choice is that Qwen3 is released in both dense and MoE forms. [8]

5.1 MoE: choose a few feed-forward networks for each token

An MoE layer replaces one large feed-forward network with many experts. A router scores the experts for each token and sends the token to only the best few. Qwen3’s released MoE models have 128 experts and select eight per token. That gives the model a large total parameter pool while keeping the per-token calculation much smaller than running every expert.

token state→router
scores experts→E₁E₂E₃E₄E₅E₆→weighted sum
y = Σi ∈ TopK(r(x)) softmax(r(x))i · Ei(x)

The router needs balancing. If a few experts receive nearly all tokens, those experts become overloaded and the rest do not learn. Qwen3 uses global-batch load balancing, which measures routing across a wider batch rather than correcting every small local batch independently.

Qwen3’s thinking and non-thinking modes belong in a different box from this architecture. They are learned through a four-stage post-training process that includes a reasoning cold start, reinforcement learning, fusion with direct-answer data, and general RL. The same model weights can be prompted to show a reasoning trace or answer directly. This changes output behaviour and token budget, not the attention calculation. [9]

5.2 Qwen3-VL: send visual features into more than one language layer

Qwen3-VL keeps the vision encoder, merger, and Qwen3 decoder structure, but adds DeepStack. Instead of sending only the final vision-encoder features into the LLM, DeepStack injects features from several vision depths into corresponding language layers. Early visual layers can contribute local texture and text detail, while later layers contribute more abstract objects and relations. Interleaved M-RoPE and text timestamps extend the position scheme to long mixed image, video, and text histories. [10]

6. Qwen3-Next: use recurrence for most layers, attention at intervals

Qwen3-Next is the first large change to the sequence operator. Its 80B-A3B model repeats three Gated DeltaNet layers followed by one Gated Attention layer. DeltaNet carries a bounded recurrent state forward, so it can process a sequence without rereading every earlier token at full attention cost. Gated Attention still performs content-addressed retrieval, but only periodically. This combination gives the model a cheap continuous memory path and regular opportunities to retrieve a precise earlier item.

6.1 Gated DeltaNet: update a memory state instead of storing every pairwise comparison

In full attention, each token compares its query with many earlier keys. A DeltaNet layer instead maintains a state matrix S. A new token writes a key-value association into that state, while a learned gate decides how much old state to retain. The query reads from the updated state. This is linear in sequence length for a fixed state size, but it cannot keep every past token as an independently addressable entry.

St = gt ⊙ St−1 + ktvtT
ot = qtTSt
The gate controls retention. The exact implementation includes a delta-style write rule.

The periodic Gated Attention layers make up for the recurrent state’s limitation. They can look up a particular distant token or passage directly. Qwen3-Next also uses 512 routed experts, selects 10, includes one shared expert, and adds multi-token prediction. MTP trains an auxiliary head to predict several future tokens, which can later support faster speculative generation. [11]

7. Qwen3.5, 3.6, 3.7, and 3.8: retain the hybrid template

The later point releases should not be presented as four different Transformers. Qwen3.5 brings the Qwen3-Next hybrid of three Gated DeltaNet layers and one Gated Attention layer into a unified vision-language foundation. It retains sparse MoE, MTP, and a native 262K context that can extend toward one million tokens. [12]

Qwen3.6 retains that core layout. Its public release emphasises post-training and agent ergonomics, including keeping relevant reasoning history through tool use, rather than a new sequence block. Qwen3.7 is a hosted-product waypoint in the current public record, so this guide does not invent an architecture claim for it. Qwen3.8 scales the same template to 2.4T total parameters with 95B active parameters. The useful conclusion is that scale and training changed, while the published hybrid backbone remained recognisable. [13] [14]

8. Qwen3.8-Flash-Next: retrieve useful micro-blocks and add static n-gram memory

Qwen3.8-Flash-Next is the next clear architecture break. It is described as an experimental preview of Qwen4. It keeps Gated DeltaNet, but replaces the periodic Gated Attention leg with Qwen Sparse Attention, or QSA. QSA groups the history into micro-blocks, uses a small indexer to retrieve promising blocks, and runs more expensive attention only on the retrieved material. It is therefore closer to a retrieval system than full global attention, while retaining a recurrent path for continuous sequence processing. [15]

token stream
Gated DeltaNet→QSA indexer
ranks micro-blocks→Top-K blocks
small candidate set→sparse read
precise evidence

It also adds a four-branch gated residual design. Several transformed paths can contribute to the layer output, and gates control their mixture. An n-gram embedding table stores frequent 2-, 3-, and 4-token patterns outside the main accelerator-resident Transformer parameters. That gives repeated local patterns a cheap static memory path. It is not a replacement for reasoning over the prompt. It complements the dynamic state and sparse retrieval mechanisms.

The published model activates 6B backbone parameters per token from a 125B backbone, with an additional 51B n-gram embeddings and a 4B multi-step prediction module. Those figures illustrate the design goal: make the active calculation much smaller than the total available knowledge and pattern capacity. [15]

How to read the lineage. GQA changes how much cached attention state is stored. M-RoPE changes how visual position is represented. MoE changes which feed-forward weights a token activates. DeltaNet changes the default way history is carried forward. QSA changes how the model retrieves detailed evidence from a long history. Keeping these questions separate prevents “efficient” from becoming an empty label.
