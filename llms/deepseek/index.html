DeepSeek’s useful contribution is not a single trick. It is a repeated habit: locate the system constraint that will dominate at the next scale, then reshape the model, training objective, kernels, and serving path around it.

Scope note“V1” is convenient shorthand for the 2023 DeepSeek LLM dense family. V2 is included because it introduces MLA and DeepSeekMoE; V3 scales that recipe. R1 is a post-training methodology rather than a new Transformer backbone.

1. The paradigm: design around the bottleneck

At small scale, parameter count and training data are the story. At serving scale, each generated token must read an ever-growing cache from memory. At trillion-scale MoE, all-to-all routing can dominate a step. At extreme depth, residual streams become an optimization problem. DeepSeek’s architecture sequence is best read as answers to those changing constraints.

“Open” does not mean each release exposes exactly the same artifacts. The papers, model cards, weights, and inference references make different parts of the stack inspectable. This guide keeps architecture claims tied to those first-party records rather than inferring them from benchmark tables.

2. Dense foundations: DeepSeek LLM & DeepSeek-VL

2.1 DeepSeek LLM: establish the base recipe

The original DeepSeek LLM release trained dense 7B and 67B base models on 2 trillion tokens, then made chat variants with supervised fine-tuning and direct preference optimization. Its scaling-law work compared data scaling and model shapes so the 67B run could spend compute where it mattered. [1]

7B / 67B dense models2T pre-training tokens4K contextSFT + DPO chat alignment

There is no sparsity or latent attention here: ordinary multi-head attention keeps a separate key and value cache for each head. It is a useful baseline because later cache figures only make sense against this “store everything per layer, per token” design.

2.2 DeepSeek-VL: make vision part of pre-training

DeepSeek-VL attaches a hybrid vision encoder to the language model and feeds visual embeddings alongside text during the early multimodal stage, instead of treating vision as a late adapter. Its high-resolution path operates at 1024 × 1024 and uses a 3 × 3 pixel-unshuffle operation to reduce visual token count by 9× before the language-model side. [2]

Its practical coverage—web screenshots, documents, OCR, charts, and knowledge—is a useful precursor to V4.1-Flash, which is natively multimodal rather than a text-only agent model with an auxiliary vision interface.

3. Sparse scaling: V2’s ideas, V3’s scale

3.1 MLA: cache the latent, not reconstructed K/V

Autoregressive decoding often becomes memory-bandwidth bound: the next token reads historical keys and values from every layer. MHA caches separate K/V states for every head; MQA and GQA reduce duplication by sharing them. Multi-Head Latent Attention (MLA), introduced in DeepSeek-V2, down-projects a token’s K/V state to a compact latent ctKV. That latent is cached; the model performs the appropriate reconstructed computation at attention time. [3]

LOW-RANK KV COMPRESSION

ctKV = WdownKVht   ;   KtC, VtC = WupK,VctKV

RoPE makes this factorization nontrivial: its position-dependent rotation cannot simply be absorbed into a shared low-rank projection. MLA therefore splits out a small decoupled positional key/query path. The cache contains the latent content state plus the position-carrying key component, preserving rotary positions while avoiding a full per-head K/V cache.

ATTENTION WHAT IS CACHED DECODE TRADE-OFF
MHA independent K/V per head maximum flexibility, highest bandwidth
GQA fewer shared K/V heads simple middle ground
MLA KV latent + decoupled positional key compression with richer head structure

3.2 DeepSeekMoE: more specialists, fewer active weights

DeepSeekMoE breaks the feed-forward layer into finer-grained routed experts and keeps shared experts always available. The fine granularity gives the router more combinations of specialists at comparable active compute. V3 uses 671B total parameters but activates 37B per token. [4]

token state→router
selects experts→
sharede₁e₂e₃…
→mixed update

Standard MoE training often adds an auxiliary load-balancing loss. That keeps traffic even, but can compete with the main objective. V3 instead maintains a per-expert bias: overloaded experts are made less likely and underloaded experts more likely at routing time; the bias is updated from observed load without adding that penalty to the main loss. This is “auxiliary-loss-free,” not load balancing without any control signal.

3.3 Multi-token prediction: densify the learning signal

V3’s MTP module predicts several future tokens with a sequential dependency rather than merely adding independent next-token heads. During training that supplies a denser objective; at inference the extra module can act as a speculative draft proposal. The full V3 run used 14.8T tokens and 2.788M H800 GPU-hours for complete training. [4]

4. DeepSeek-R1: reasoning as an optimization target

4.1 R1-Zero: start with rewards, not demonstrations

DeepSeek-R1-Zero applies large-scale RL directly to a base model, before supervised fine-tuning. For verifiable problems, rewards can judge the outcome while leaving the route to the model. Using Group Relative Policy Optimization (GRPO), a group of sampled answers provides the relative baseline, avoiding a separate learned critic. [5]

prompt→sample a group→verify outcomes→relative advantage
updates policy

The important reported behavior is extended chains of thought, reflection, answer checking, and changing strategy without human-written reasoning traces. But pure RL also created language mixing, readability issues, and repetitive loops. Emergence is not the same as a finished user experience.

4.2 R1: cold start, RL, and consolidation

DeepSeek-R1 starts from a small, curated cold-start set with readable chain-of-thought formatting. It then alternates supervised stages, GRPO reasoning training, rejection sampling, and a final all-scenarios RL phase. R1 is not “R1-Zero plus more RL”; the cold start controls format and the later pipeline broadens capability while keeping the reasoning policy.

4.3 Distillation: transfer the behavior, not only answers

R1 reasoning traces were distilled into dense Qwen and Llama models from 1.5B through 70B parameters. The paper’s lesson is unusually direct: smaller models trained on long-CoT outputs can beat same-size models trained only on human demonstrations. The teacher supplies a distribution of reasoning behavior that a plain answer label does not contain. [5]

5. DeepSeek-V4: million-token context & depth stability

V4 moves the bottleneck from ordinary decode caching to long-context attention itself. The released family has a 1M-token context window: V4-Flash is 284B total / 13B active, and V4-Pro is 1.6T total / 49B active. Both were pre-trained on more than 32T tokens. [6]

5.1 Hybrid attention: global selectivity, local density

V4 combines Compressed Sparse Attention (CSA) and Heavily Compressed Attention (HCA) to make global context economically usable. CSA gives a query a learned sparse view of faraway context; HCA supplies a highly compressed global path. In the official 1M-token comparison, V4-Pro reports 27% of V3.2’s single-token inference FLOPs and 10% of its KV cache. [6]

5.2 mHC: make the residual pathway a controlled mixing system

Manifold-Constrained Hyper-Connections replace a single residual stream with n streams, then learn how blocks read, transform, and write across that collection. The mixing matrices are constrained to the Birkhoff polytope—doubly stochastic matrices—so their operator behavior does not freely amplify or collapse signals through depth. In short: more information routes, with a geometric constraint that keeps an ultra-deep network trainable. [7]

RESIDUAL STREAM MULTIPLICITY

Xl ∈ ℝn×d   →   Xl+1 = Hl(Xl),   with constrained stream-mixing maps

V4 also uses Muon on hidden linear layers. Muon preconditions matrix updates through an operator-norm-oriented transform; the point in this context is faster, more stable progress for the large matrix parameters that dominate the network. [6]

6. V4.1-Flash: compress the agent backbone

Released September 10, 2026, V4.1-Flash is a 552B-backbone multimodal MoE with a 1M-token context. Its central move is to acknowledge that prefill and decode are different workloads. Long-running agents ingest huge prompt histories, but only decode one token at a time. [8] [9]

6.1 Causal Encoder–Decoder: split prefill from decoding

The 40-layer backbone is organized as a 20-layer causal encoder followed by a 20-layer decoder. Global decoder K/V is projected from the final encoder hidden state rather than independently derived in each decoder layer. The model therefore activates 8B parameters per token in prefill and 16B in decode—an asymmetric budget tuned for input-heavy agent traces.

→ global KV projection →
20 decoder layersdecode · 16B active/token

6.2 CSA2: reuse work across layers

CSA2 turns sparse-attention indexing into a shared, three-mode schedule. A Full layer writes fresh main K/V, indexer K/Q, and Top-K locations. A Reindex layer reuses main K/V and indexer K but evaluates its own indexer Q to select fresh locations. A Reuse layer consumes both the preceding main K/V and selected locations, skipping indexer work. In decoder layers, a hierarchical indexer limits deeper searches to a candidate pool chosen by an earlier Full layer. [9]

Fullnew KV · K/Q · Top-K
Reindexreuse KV/K · new Q / Top-K
Reusereuse KV and Top-K

FP4 main-KV caching is trained with QAT in OCP MXFP4 E2M1 format, using one E4M3 scale per 16 channels. Together these mechanisms bring the stated global cache footprint to 890 bytes per token: about ¼ of V4-Flash and 1/437 of the dense V1 baseline in the release comparison. Cache numbers are a model-specific comparison—not a universal ranking of all attention implementations.

6.3 Keep only the history that has value

SWA Bounded Replay does not persist every local-window K/V state to SSD. It reconstructs missing local states by replaying only the latest nwin tokens, reducing persistent cache to about ⅛ of V4-Flash. Single-Pass mHC shifts input mixing coefficients by one block so residual mixing no longer needs a separate dependency pass; Mega-mHC is its efficient fused implementation.

Engram is a conditional n-gram memory table with 196B parameters, sparsely consulted through token-based lookup. It separates static memorization from the transformer’s dynamic computation. DSpark is a semi-autoregressive speculative decoder that drafts multiple tokens and applies confidence-scheduled verification. These are different levers—memory, cache persistence, kernel traffic, and token generation—not one generic “compression” trick. [9]

6.4 Post-training: make thought length a runtime dial

V4.1-Flash uses the familiar SFT → RL → on-policy-distillation sequence, while scaling data synthesis for agent tasks and environments. Its public interface exposes integer reasoning effort from 1 to 100, letting a caller trade tokens and latency against problem-solving budget. That setting is a deployment policy choice, not an assurance that every task needs maximum reasoning. [9]

Selection heuristic. Use a dense model when simplicity, hardware fit, or short context dominates. Choose V3-style MLA/MoE where serving memory and active compute bind. Use R1-style reasoning or distillation when the task has reliable verification. For very long, tool-heavy traces, V4 and V4.1’s context and cache design matter more than a headline parameter count; set reasoning effort to the smallest budget that reliably clears the task.
