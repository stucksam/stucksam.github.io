This guide follows what changed inside the models. It begins with the dense text and vision models, then explains how later releases reduce cache memory, select expert networks, train reasoning behavior, and process very long agent histories.

Scope note“V1” is convenient shorthand for the 2023 DeepSeek LLM dense family. V2 is included because it introduces MLA and DeepSeekMoE; V3 scales that recipe. R1 is a post-training methodology rather than a new Transformer backbone.

1. What changes from one generation to the next

The first DeepSeek models use the standard dense Transformer pattern. Later releases address specific costs that emerge as models and context windows grow. A long prompt makes the KV cache expensive to read. An MoE layer needs to choose experts without overloading a few of them. A reasoning model needs a reliable way to reward good answers. A million-token agent must control both computation and storage across a very long history.

2023Dense LLM7B / 67B · 2T tokens
2024V2 → V3MLA · MoE · MTP
2025R1GRPO · reasoning RL
2026V4CSA · mHC · 1M context
Sep ’26V4.1-FlashCED · CSA2 · 890 B/token

1.1 The costs the later models address

For each generated token, a dense decoder reads the saved attention state for all earlier tokens. In MoE, each token must be sent to a small set of expert networks, and the training system must keep those experts in use. In reinforcement learning, a verifier must turn a complete response into a stable update. Later designs retain the normal Transformer operations where they work and change the part that has become expensive.

THE BOTTLENECK MAP

“Open” does not mean each release exposes exactly the same artifacts. The papers, model cards, weights, and inference references make different parts of the stack inspectable. This guide keeps architecture claims tied to those first-party records rather than inferring them from benchmark tables.

2. DeepSeek LLM and DeepSeek-VL: the dense foundation

2.1 DeepSeek LLM: a text model before the sparse models

DeepSeek LLM is the starting point for this lineage: a dense, decoder-only Transformer released in 7B and 67B sizes. “Dense” means every token passes through the same attention and feed-forward weights at every layer. It was trained on 2 trillion tokens, then adapted into chat models with supervised fine-tuning and DPO. The release also reports a scaling study used to choose the size and data budget for the 67B run. [1]

7B / 67B dense models2T pre-training tokens4K contextSFT + DPO chat alignment

2.1.1 The dense decoder: what one layer does

Each layer receives one vector for every input token. It first lets the vector at position t read selected vectors from earlier positions. It then applies a separate feed-forward transformation to that token alone. Both results are added back to the running token vector through residual connections. Repeating this process lets later layers combine local syntax, long-range references, and task-specific patterns. “Causal” simply means the token at t can read tokens 1 through t, never a future token.

CAUSAL SELF-ATTENTION

Q = XWQ,   K = XWK,   V = XWV
Attn(X) = softmax((QKT / √dk) + Mcausal)V

X is the current sequence of token vectors. For each token, the model creates a query, key, and value. The query is compared with earlier keys; the resulting scores are converted into weights; those weights combine the earlier values. The causal mask makes every future score effectively zero. Multiple heads run this calculation with different projections, then the layer combines the head outputs. This is not a database lookup: the model learns the projections that decide what “relevant” should mean.

1Attendread useful earlier token states
2Mixadd the attention update through a residual path
3Transformapply the per-token non-linear feed-forward block
4Repeatdeeper layers compose broader abstractions

When generating text, the model does not recompute the keys and values for all previous tokens. It saves them in a KV cache. Generating the next token still requires reading that saved history in every layer. With a short prompt, this is cheap. With a long prompt, moving the cache from GPU memory can cost more time than the arithmetic in the layer. Later DeepSeek attention designs change what is stored in this cache; this first model provides the straightforward baseline.

DENSE PRE-TRAINING OBJECTIVE

LNTP = − Σt=1T log pθ(xt | x<t)

The loss trains the model to assign a high probability to the actual next token. Over a very large corpus, that requires useful internal representations of language, code, facts, formatting, and common problem structures. For a fixed training budget, adding parameters without enough data wastes capacity; adding data without enough model capacity also wastes compute. DeepSeek LLM’s contribution at this stage was a carefully scaled, openly reported dense run—not a new attention mechanism. [1]

2.1.2 From base model to chat model

Pre-training teaches continuation, not necessarily helpful interaction. Supervised fine-tuning gives the model examples of an instruction and a desired response. DPO then presents two responses to the same prompt: one preferred and one rejected. It adjusts the model so the preferred response becomes more likely than the rejected one. These stages change the model’s response distribution; they do not add a new attention layer or alter the underlying dense decoder.

LDPO = −log σ(β [log πθ(y+|x) − log πθ(y−|x) − reference offset])

The reference term compares the updated model with the base model. It prevents a small preference dataset from pulling the model too far away from the broad behavior learned during pre-training. The result is a chat model built on the same architecture, with a different output preference.

2.2 DeepSeek-VL: make vision part of pre-training

DeepSeek-VL adds an image encoder in front of the language model. The image encoder turns pixels into a grid of vectors; a projector converts those vectors into the same width used by text tokens. The language model then receives one sequence containing image vectors and text vectors. It can answer a question about an image because its normal attention layers can read both types of vector. DeepSeek-VL uses a hybrid vision encoder with a high-resolution 1024 × 1024 path and a lower-cost path for ordinary images. [2]

image
high resolution→3×3
pixel-unshuffle→vision
embeddings→joint LM
sequence

The high-resolution path must reduce the number of vectors before handing them to the language model. A 3 × 3 pixel-unshuffle takes each nine-neighbour patch in a feature map and places its values in the channel dimension. A feature map of height H and width W becomes H/3 by W/3; the channel count grows by nine. This preserves the local values while reducing the number of positions by 9×. Fewer positions mean fewer visual tokens and a much smaller attention cost.

VISUAL TOKENS JOIN THE TEXT STREAM

Zimage = Project(VisionEncoder(PixelUnshuffle(I)))
X = [Zimage ; Embed(x1) ; … ; Embed(xT)]

After projection, there is no separate visual answer head. Image vectors occupy positions in the same sequence as text vectors. A later attention layer can therefore connect the word “total” in a question with numbers in a chart or a table in a document. The final text token is still generated by the language model’s usual output head.

Training choice. DeepSeek-VL introduces image/text examples during multimodal pre-training instead of teaching the visual interface only after a text model is finished. This gives the shared decoder time to learn how image vectors and text vectors relate while retaining ordinary language training in the mix. The paper evaluates the resulting model on screenshots, documents, OCR, charts, and knowledge tasks. [2]

V4.1-Flash later makes this style of image-and-text processing part of a much larger agent model. The practical constraint remains the same: a higher-resolution image is only useful if the system can reduce it to a manageable number of tokens without discarding the detail needed for the task.

3. V2 and V3: reduce memory and compute per token

V2 introduces the two structural changes that V3 later scales: Multi-Head Latent Attention for the attention cache and DeepSeekMoE for the feed-forward layers. V3 keeps those two structures, then changes how the experts are balanced and how the model is trained. Separating those contributions matters: MLA and DeepSeekMoE are V2 inventions; V3 is the much larger implementation of that direction.

3.1 MLA: store a smaller representation of the past

In standard attention, every layer saves keys and values for every earlier token. MLA changes the saved object. Instead of writing all of those key/value vectors into the cache, it first compresses the token state into a smaller vector ctKV. This smaller vector is what remains in memory. When a later token needs to attend to the past, the layer uses learned projections of the saved vector to perform the required key/value computation. [3]

LOW-RANK KV COMPRESSION

ctKV = WdownKVht   ;   KtC, VtC = WupK,VctKV

Position information needs special treatment. Rotary position embeddings rotate a vector differently at each location, so they cannot be folded into one shared compressed representation without changing the attention calculation. MLA therefore keeps a small position-carrying key separate from the compressed content vector. The query and key each have a content part and a position part; attention adds the two matching signals together.

More concretely, the compressed vector is expanded into content keys and values. A separate small key carries RoPE. The layer then compares a content query with content keys and a position query with position keys. This preserves relative-position behavior while avoiding a full cached key/value tensor for every head and past token.

qt = [qtC ; RoPE(qtR)]   ;   kt = [WupKctKV ; RoPE(ktR)]

Some of the linear reconstruction can also be rearranged into the query-side calculation, so an implementation need not materialize every reconstructed key. The core idea is simpler than the algebra: keep a narrow representation in the persistent cache, and do the wider computation only when the current token needs it.

3.2 DeepSeekMoE: choose feed-forward weights per token

In a dense Transformer, every token runs through the same feed-forward network after attention. In an MoE layer, the feed-forward network is split into many smaller networks called experts. A router reads the token vector, assigns scores to experts, and sends that token to only the selected experts. DeepSeekMoE also keeps shared experts that every token uses. V3 has 671B parameters in total, but executes about 37B for a given token. [4]

token state→router
selects experts→
sharede₁e₂e₃…
→mixed update

Without a balancing mechanism, a router can keep selecting a few popular experts. Those experts then become overloaded while other parameters receive little training. A common solution adds a second loss that rewards even traffic. V3 does not add that loss to the optimization target. Instead, it changes the router’s expert scores with a per-expert bias: if an expert received too much traffic, its bias is lowered for the next update; if it received too little, its bias is raised. The main language-model loss remains responsible for deciding which experts are useful.

SPARSE EXPERT MIXTURE

y = FFNshared(x) + Σi ∈ TopK(x) gi(x) · FFNi(x)

The router produces a score for every routed expert, keeps the highest-scoring K, and uses the normalized scores gi to mix their outputs. The shared output is added for every token. “671B total / 37B active” therefore describes two different quantities: total stored capacity and the computation used by one token. This is how the model can grow its parameter count without paying the full dense-model compute cost on every token.

3.3 Multi-token prediction: densify the learning signal

V3 adds a multi-token prediction (MTP) module. The normal language-model loss teaches position t to predict only the next token. MTP also asks the model to predict several later tokens in order. During inference, those additional predictions can be used as a draft that the main model checks. The full V3 run used 14.8T tokens and 2.788M H800 GPU-hours for complete training. [4]

Ordinary next-token prediction gives the hidden state at position t one direct target: xt+1. MTP adds targets for the next D positions while preserving a causal chain between prediction depths. That asks the representation at t to remain useful slightly farther into the future, rather than treating “next” as the only learning horizon.

LMTP = − Σt Σk=1D log pθ(xt+k | x≤t, xt+1…t+k−1)

At serving time, the same extra prediction depths can propose a short continuation. The larger model then verifies that proposal in parallel. If it agrees on several tokens, the server advances several positions at once; if it disagrees, it falls back to the accepted prefix. MTP therefore links a training objective to a potential decoding speedup, although the main model remains the authority.

4. DeepSeek-R1: reasoning as an optimization target

4.1 R1-Zero: start with rewards, not demonstrations

DeepSeek-R1-Zero applies large-scale RL directly to a base model, before supervised fine-tuning. For verifiable problems, rewards can judge the outcome while leaving the route to the model. Using Group Relative Policy Optimization (GRPO), a group of sampled answers provides the relative baseline, avoiding a separate learned critic. [5]

prompt→sample a group→verify outcomes→relative advantage
updates policy

For a prompt q, GRPO samples a group of outputs o1…oG from the old policy. A verifier supplies rewards ri—for example, whether a mathematical answer is correct or a program passes tests. Each result is judged relative to its peers in the same group:

GROUP-RELATIVE ADVANTAGE

Ai = (ri − mean(r1…G)) / (std(r1…G) + ε)

A correct completion in a mostly incorrect group receives a positive advantage; a weak completion in a strong group receives a negative one. This replaces the learned value network used by many actor-critic methods with a within-group baseline. It is especially practical when the reward is cheap and reliable but step-by-step human reasoning labels are not.

SIMPLIFIED GRPO UPDATE

maxθ E[ min(ρiAi, clip(ρi, 1−ε, 1+ε)Ai) − βDKL(πθ || πref) ]
ρi = πθ(oi|q) / πold(oi|q)

The ratio ρ asks how much more or less likely the updated policy makes an already sampled output. Clipping prevents a single update from changing that probability too aggressively. The KL term anchors the policy to a reference model so reward hacking does not immediately erase useful language behavior. This is the optimization machinery behind the headline “RL without SFT,” not a claim that the model somehow learns without supervision: the verifier is still a crucial source of signal.

The important reported behavior is extended chains of thought, reflection, answer checking, and changing strategy without human-written reasoning traces. But pure RL also created language mixing, readability issues, and repetitive loops. Emergence is not the same as a finished user experience.

4.2 R1: cold start, RL, and consolidation

DeepSeek-R1 starts from a small, curated cold-start set with readable chain-of-thought formatting. It then alternates supervised stages, GRPO reasoning training, rejection sampling, and a final all-scenarios RL phase. R1 is not “R1-Zero plus more RL”; the cold start controls format and the later pipeline broadens capability while keeping the reasoning policy.

4.3 Distillation: transfer the behavior, not only answers

R1 reasoning traces were distilled into dense Qwen and Llama models from 1.5B through 70B parameters. The paper’s lesson is unusually direct: smaller models trained on long-CoT outputs can beat same-size models trained only on human demonstrations. The teacher supplies a distribution of reasoning behavior that a plain answer label does not contain. [5]

5. DeepSeek-V4: attention that can use a million-token prompt

A million-token context is not useful if reading it costs too much for each generated token. V4 changes the attention path so a token does not compare itself with every past token at full cost. The public family includes V4-Flash (284B total parameters, 13B active) and V4-Pro (1.6T total, 49B active), both with a 1M-token context window and more than 32T pre-training tokens. [6]

5.1 Hybrid attention: select distant information and compress the rest

V4 uses two global attention paths. Compressed Sparse Attention (CSA) uses an index to select a small set of relevant positions from the distant history, then reads those positions in more detail. Heavily Compressed Attention (HCA) carries a compact summary of the broader history. The model can therefore preserve direct access to selected long-range facts while maintaining a lower-cost global signal for everything else. In DeepSeek’s reported 1M-token comparison, V4-Pro uses 27% of V3.2’s single-token inference FLOPs and 10% of its KV cache. [6]

5.2 mHC: use several residual streams without destabilising depth

A normal residual block carries one main vector forward and adds a learned update to it. mHC keeps several parallel residual vectors. A block reads a mixture of these vectors, computes its update, and writes mixtures back to them. This creates more routes for information than a single residual stream, but it also introduces a risk: repeated unrestricted mixing can amplify or erase signals as the number of layers grows. [7]

RESIDUAL STREAM MULTIPLICITY

Xl ∈ ℝn×d   →   Xl+1 = Hl(Xl),   with constrained stream-mixing maps

A standard residual block is xl+1 = xl + Fl(xl). Hyper-connections replace x with a set of streams and use matrices to mix them before and after F. mHC constrains those matrices to be non-negative and to have rows and columns that sum to one. The constraint means a matrix can redistribute information across streams but cannot arbitrarily scale the total signal up or down. That preserves the stabilising role normally played by the identity residual path.

V4 also uses Muon for hidden linear layers. At a high level, Muon changes the direction and scale of matrix updates so training can make progress without unstable parameter changes. It is an optimization choice, separate from CSA/HCA attention and separate from the residual-stream design. [6]

6. DeepSeek-V4.1-Flash: reduce the cost of long-running agents

Released September 10, 2026, V4.1-Flash is a 552B-backbone multimodal MoE with a 1M-token context. It is designed around the fact that an agent spends time in two very different phases. First it reads a large prompt, tool history, and files. Then it generates a response one token at a time. V4.1 uses different amounts of computation and different cache layouts for those two phases. [8] [9]

6.1 Causal Encoder–Decoder: read the prompt once, reuse its result

The 40 Transformer layers are split into 20 causal encoder layers and 20 decoder layers. During prefill, the encoder reads the input sequence and produces final hidden states. The decoder’s global keys and values are projected from those encoder states instead of being independently built from every decoder layer’s own hidden states. This changes where global history is stored and reduces the work required to ingest a long prompt.

→ global KV projection →

6.2 CSA2: share the expensive search between layers

Sparse attention needs an indexer: a smaller computation that decides which past positions are worth reading. CSA2 gives each attention layer one of three fixed jobs. A Full layer creates new main keys/values, indexer keys and queries, and a new Top-K list of positions. A Reindex layer reuses the main keys/values and indexer keys from a previous layer, but uses its own query to choose a new Top-K list. A Reuse layer uses both the existing keys/values and the existing Top-K list. It does not run the indexer at all. [9]

Fullnew KV · K/Q · Top-K
Reindexreuse KV/K · new Q / Top-K
Reusereuse KV and Top-K

Later decoder layers use a hierarchical index: they search only within a candidate set selected by an earlier Full layer. This prevents every layer from scanning the entire million-token history. The main cache is also stored in FP4, with quantization-aware training preparing the model for that low-precision format. DeepSeek reports a global cache footprint of 890 bytes per token—about one quarter of V4-Flash in its measurement. This is a measurement for this specific architecture and cache layout, not a universal comparison of all attention implementations.

6.3 Do not persist cache state that can be cheaply rebuilt

Sliding-window attention needs a recent local history. Persisting that local KV state for a long agent trace would consume substantial SSD storage. SWA Bounded Replay instead rebuilds missing local state by replaying only the most recent nwin tokens. DeepSeek reports that this reduces persistent cache storage to roughly one eighth of V4-Flash. Single-Pass mHC similarly reduces memory traffic inside the residual mixing calculation by arranging the mixing coefficients so the implementation needs fewer separate passes.

Engram is a conditional n-gram table with 196B parameters. A token pattern can look up a small part of that table, rather than asking the Transformer to store every frequent continuation in its active computation. DSpark is a speculative decoding method: it drafts several tokens, then verifies them with the main model according to a confidence schedule. These pieces solve different problems: Engram stores conditional memorized patterns; bounded replay controls persistent cache size; DSpark reduces the number of full decode steps. [9]

6.4 Post-training: make thought length a runtime dial

V4.1-Flash uses SFT, reinforcement learning, and on-policy distillation, with synthetic agent tasks and environments used to create more training situations. Its public interface exposes integer reasoning effort from 1 to 100. A larger setting gives the model a larger thinking budget; it can also increase latency and generated-token cost. The right setting depends on whether a task benefits from additional verification and planning. [9]

Selection heuristic. Use a dense model when simplicity, hardware fit, or short context dominates. Choose V3-style MLA/MoE where serving memory and active compute bind. Use R1-style reasoning or distillation when the task has reliable verification.
